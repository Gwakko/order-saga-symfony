# M6.1. Спайк: RoadRunner + PHP SDK + ext-grpc

## Сделано
- `docker/php/Dockerfile`: `install-php-extensions ... grpc protobuf` и `COPY --from=ghcr.io/roadrunner-server/roadrunner:3.0.1 /usr/bin/rr /usr/local/bin/rr`.
- `.rr.yaml` (`version: "3"`, `server.command: php bin/temporal-worker.php`, `temporal.address: ${TEMPORAL_ADDRESS:-temporal:7233}`, `rpc.listen: tcp://127.0.0.1:6001`).
- `bin/temporal-worker.php`: `Dotenv::bootEnv`, `new Kernel(...)->boot()`, `WorkerFactory::create()`, `newWorker('order-saga')`, `registerWorkflowTypes`, `registerActivity(Impl::class, factory из контейнера)`, `registerActivityFinalizer` (сбрасывает `services_resetter`), `$factory->run()`.
- Compose: сервис `temporal-worker` (образ php, `command: rr serve -c .rr.yaml`, `depends_on` postgres/redis/temporal). Он НЕ в профиле `workers`: проверка M6.1 запускает его обычным `up -d temporal temporal-worker`; профиль `workers` и существующие сервисы не тронуты.
- `src/Saga/Infrastructure/Temporal/TemporalClientFactory.php` (`WorkflowClient::create(ServiceClient::create($address), ClientOptions->withNamespace())`), `Hello/{HelloWorkflow,HelloWorkflowImpl,HelloActivity,HelloActivityImpl,Greeter}`, `src/Saga/Infrastructure/Console/TemporalHelloConsoleCommand` (`app:temporal:hello [name]`).
- `config/services.yaml`: аргумент `$address: '%env(TEMPORAL_ADDRESS)%'` у фабрики; `HelloActivityImpl` объявлен `public: true` (воркер берёт активность из контейнера).
- `.env` уже содержал `TEMPORAL_ADDRESS=temporal:7233`.

Порядок слоёв в Dockerfile важен: менять строку `install-php-extensions` нельзя без повторных ~17 минут. Gateway-эмулятор (`php:8.5-cli-alpine`) расширения не требует.

## Точные имена и сигнатуры (проверено по `vendor/temporal/sdk`, v2.20)
Пространства имён и классы:
- **`Temporal\Workflow\Saga`**: `final class Saga`; `setParallelCompensation(bool): self`, `setContinueWithError(bool): self`, `addCompensation(callable $handler): void`, `compensate(): CancellationScopeInterface`. Конструктора с аргументами нет (в спеке `new Saga(parallelCompensation: false)` НЕ существует; параллельность через сеттер). `compensate()` возвращает scope, его надо `yield`-ить. Каждый обработчик выполняется через `Workflow::asyncDetached($handler)`, значит он должен быть генератором (`yield $activity->...`), а не просто вызовом. Последовательный режим идёт с конца (LIFO); при ошибке компенсации: без `continueWithError` исключение пробрасывается сразу, с ним собирается `Temporal\Exception\CompensationException` (suppressed = остальные).
- **`Temporal\Activity\ActivityOptions`**: `ActivityOptions::new()` (из `Internal\Support\Options::new(): static`); `withTaskQueue(?string)`, `withScheduleToCloseTimeout($t)`, `withScheduleToStartTimeout($t)`, `withStartToCloseTimeout($t)`, `withHeartbeatTimeout($t)`, `withCancellationType(ActivityCancellationType|int)`, `withActivityId(string)`, `withRetryOptions(?RetryOptions)`, `withPriority`, `withSummary`. Стаб: `Workflow::newActivityStub(string $class, ?ActivityOptionsInterface $options = null): object`; нетипизированный `Workflow::newUntypedActivityStub`.
- **`Temporal\Common\RetryOptions`**: `RetryOptions::new()`; `withInitialInterval($i)`, `withBackoffCoefficient(float)`, `withMaximumInterval($i)`, `withMaximumAttempts(int)`, `withNonRetryableExceptions(array<class-string<\Throwable>>)`. Список по умолчанию пуст. Совпадение идёт по типу ошибки (имя класса исключения активности, у `ApplicationFailure` поле `type`).
- **Интервалы**: целое число = **миллисекунды** (`Internal\Support\DateInterval::parse`, формат по умолчанию `FORMAT_MILLISECONDS`). `withWorkflowExecutionTimeout(60)` это 60 мс. Использовать `Carbon\CarbonInterval::seconds(10)` (или `\DateInterval`). Для конфигурации (`%env%`/параметры в секундах) нужна явная конвертация.
- **Политика повторного использования workflow id**: класса `WorkflowIdReusePolicy` НЕТ. Это `Temporal\Common\IdReusePolicy` (enum `int`): `Unspecified=0, AllowDuplicate=1, AllowDuplicateFailedOnly=2, RejectDuplicate=3, TerminateIfRunning=4`. Опция: `WorkflowOptions::withWorkflowIdReusePolicy(IdReusePolicy|int)`. Отдельно есть `Temporal\Common\WorkflowIdConflictPolicy` (`Unspecified=0, Fail=1, UseExisting=2, TerminateExisting=3`) с `WorkflowOptions::withWorkflowIdConflictPolicy`. `UseExisting` может заменить ловлю исключения при дубле старта (не проверено на сервере 1.10.1; рекомендация для M6.2: проверить).
- **Исключение «уже запущен»**: `Temporal\Exception\Client\WorkflowExecutionAlreadyStartedException extends WorkflowException` (конструктор `(WorkflowExecution $execution, ?string $type, ?\Throwable $previous)`, `getPrevious()` = `ServiceClientException`). Проверено на сервере: повторный старт `order-<id>` при завершённом первом запуске с `RejectDuplicate` бросает именно его; с `AllowDuplicate` стартует новый run. Клиентский вызов: `WorkflowClient::start($stub, ...$args): WorkflowRunInterface` (`getExecution()->getID()/getRunID()`, `getResult()`).
- **WorkflowOptions**: `WorkflowOptions::new()`, `withWorkflowId(string)`, `withTaskQueue(string)`, `withWorkflowExecutionTimeout($t)`, `withWorkflowRunTimeout`, `withWorkflowTaskTimeout`, `withWorkflowIdReusePolicy`, `withWorkflowIdConflictPolicy`, `withRetryOptions`, `withMemo`, `withSearchAttributes`. Стаб: `WorkflowClient::newWorkflowStub(string $class, ?WorkflowOptions $options = null)`, `newRunningWorkflowStub(string $class, string $workflowID, ?string $runID = null)`, `newUntypedWorkflowStub`, `signalWithStart`, `startWithSignal`, `updateWithStart`.
- **Атрибуты**: `#[Temporal\Workflow\WorkflowInterface]`, `#[WorkflowMethod(name: ...)]` (конструктор `?string $name`), `#[SignalMethod(?string $name = null, HandlerUnfinishedPolicy $unfinishedPolicy = WarnAndAbandon, string $description = '')]`, `#[QueryMethod(?string $name = null, string $description = '')]`, `#[UpdateMethod]`, `#[WorkflowInit]`; активности `#[Temporal\Activity\ActivityInterface(prefix: '...')]`, `#[ActivityMethod(name: ...)]`. Динамическая регистрация: `Workflow::registerSignal(string $name, callable $handler, string $description = '')`, `Workflow::registerQuery(...)`.
- **Workflow статические**: `Workflow::await(callable|Mutex|PromiseInterface ...$conditions): PromiseInterface`, `Workflow::awaitWithTimeout($intervalOrOptions, ...$conditions)`, `Workflow::timer($interval)`, `Workflow::getVersion(string $changeId, int $minSupported, int $maxSupported): PromiseInterface<int>` (константа `Workflow::DEFAULT_VERSION = -1`; результат нужно `yield`), `Workflow::now()`, `Workflow::uuid()/uuid4()/uuid7()` (Promise), `Workflow::sideEffect`, `Workflow::getLogger(): LoggerInterface` (есть), `Workflow::getInfo()`, `Workflow::async()/asyncDetached()`, `Workflow::continueAsNew`, `Workflow::newChildWorkflowStub`.
- **Исключения активности/workflow**: `Temporal\Exception\Failure\ApplicationFailure(string $message, string $type, bool $nonRetryable, ?ValuesInterface $details = null, ?\Throwable $previous = null, ?\DateInterval $nextRetryDelay = null, ApplicationErrorCategory $category = Unspecified)`; из workflow ошибка активности приходит как `Temporal\Exception\Failure\ActivityFailure` (причина в `getPrevious()`, обычно `ApplicationFailure` с `getType()`); `Temporal\Exception\Client\WorkflowFailedException`, `WorkflowNotFoundException`, `WorkflowQueryException`, `WorkflowUpdateException`, `TimeoutException`.
- **Worker**: `Temporal\WorkerFactory::create(?DataConverterInterface, ?RPCConnectionInterface, ?ServiceCredentials, ?PluginRegistry, ?WorkflowClient)`, `newWorker(...)`, `run(): int`; `WorkerInterface::registerWorkflowTypes(string ...$class)`, `registerActivity(string $type, ?callable $factory = null)` (фабрика получает `ReflectionClass`), `registerActivityFinalizer(\Closure)` (вызывается после каждой активности), `registerActivityImplementations(object ...)` (deprecated). **Ловушка**: активность надо регистрировать по классу РЕАЛИЗАЦИИ (`HelloActivityImpl::class`). Регистрация по интерфейсу падает в рантайме: `ReflectionException: Trying to invoke abstract method ...HelloActivity::greet()`.
- **Клиент и ext-grpc**: `Temporal\Client\GRPC\ServiceClient::create(string $address)` (`BaseClient::create`) без `ext-grpc` бросает `RuntimeException: The gRPC extension is required to use Temporal Client.` (проверено `php -n`). Клиентский процесс (HTTP, консоль, consumer) ТРЕБУЕТ ext-grpc, альтернативы (REST/HTTP-транспорт) в SDK нет; в `composer.json` SDK это `suggest`, не `require`. Воркер внутри RoadRunner ext-grpc не использует (RR держит соединение), но образ один, расширение стоит везде. Запасной вариант без ext-grpc: старт workflow через воркер-RPC/свой HTTP-адаптер, спека такого не требует.

## Тестовое окружение, replayer
- `Temporal\Testing\Environment` (`create()`, `startTemporalServer(...)`, `startTemporalTestServer(int $commandTimeout = 10)`, `startRoadRunner(array $rrCommand, ...)`, `stop()`, `isTemporalTestRunning()`), `Temporal\Testing\ActivityMocker` (`expectCompletion(string $activityMethodName, mixed)`, `expectFailure(string, \Throwable)`, `expectConsecutiveCompletions`, `expectCompletionWhen`), `Temporal\Testing\WorkflowMocker`, `Temporal\Testing\WorkerFactory` (тестовая версия), `Temporal\Testing\WorkflowTestCase` и `TimeSkippingWorkflowTestCase extends WorkflowTestCase`, `Temporal\Testing\TestService`.
- Без сервера тест workflow НЕ запускается: нужны (1) `temporal-test-server` (GraalVM-бинарь из релизов `temporalio/sdk-java`, НЕ в `vendor`; `Environment::startTemporalTestServer` падает с `./temporal-test-server: not found`, если файла нет); (2) процесс RoadRunner с тестовым воркером. Бинарь качается `Temporal\Testing\Downloader::download(SystemInfo::detect())` (в контейнере arm64/linux скачался, 87 МБ, предупреждения `Undefined array key 1/2` на нематчащихся ассетах безвредны), запуск `./temporal-test-server 7233 --enable-time-skipping` заработал и в контейнере `php` (отдельно от dev-сервера). Пропуск времени включён по умолчанию (`--enable-time-skipping`), управление `TestService::create('127.0.0.1:7233')->lockTimeSkipping()`. Требует доступа в сеть к `api.github.com` на этапе загрузки (лимиты API, `GITHUB_TOKEN`).
- Следствие для T-W-*: «workflow-тесты» = интеграционные, нужны test-server + RR + тестовый воркер; `make test-wf` должен это поднимать (bootstrap), либо скачивать бинарь в образ/кэш. Чисто in-process runner в SDK не найден.
- **Replayer**: `Temporal\Testing\Replay\WorkflowReplayer` (конструктор без аргументов, RPC адрес из `RR_RPC`, по умолчанию `tcp://127.0.0.1:6001`): `replayHistory(History)`, `replayFromServer(string $workflowType, WorkflowExecution)`, `downloadHistory(string $workflowType, WorkflowExecution, string $savePath)` (нужен непустой RunID), `replayFromJSON(string $workflowType, string|\SplFileInfo $path, int $lastEventId = 0)`; бросает `Temporal\Testing\Replay\Exception\ReplayerException` (подклассы в `Replay/Exception`). Проверено: `downloadHistory` + `replayFromJSON` из контейнера `temporal-worker` (`php` вызывает RPC в локальный rr) дали `replay ok` (история 5 КБ). Replayer говорит с RR по goridge, поэтому реплей-тест должен выполняться там, где доступен работающий `rr` (rpc.listen 6001), а не в голом PHPUnit.

## Symfony Kernel в воркере и сброс сервисов
- Подключение: `require vendor/autoload.php; (new Dotenv())->bootEnv(.env); $kernel = new Kernel(env, debug); $kernel->boot(); $container = $kernel->getContainer();` (без Symfony Runtime), контейнер один на процесс воркера.
- Активности берутся из контейнера: нужен `public: true` на реализации (или сервис-локатор по тегу, в M6.2 лучше через тег `app.temporal.activity` + `ServiceLocator`, чтобы не размечать каждый класс).
- Сброс: `services_resetter` (`Symfony\Component\DependencyInjection\ServicesResetter`, public) вызывается из `registerActivityFinalizer(static function () use ($container): void {...})`; финализатор запускается после каждой активности. Doctrine DBAL 4: метода `ping()` нет (`isConnected()`, `close()`, `getNativeConnection()`); переподключение = `close()` и повторное обращение (соединение ленивое), либо catch `ConnectionLost` и повтор. Механизм для M6.4.

## Отклонения от спеки
1. **RoadRunner**: бинарь v**3.0.1**, а не v2025.1.15 (`00_overview.md` §7.3). `vendor/bin/rr get-binary` с фильтром по умолчанию `3.*` ставит именно его; фильтр `2025.*` ничего не ставит. Бинарь вшит в образ из `ghcr.io/roadrunner-server/roadrunner:3.0.1`, `rr get-binary` в процессе не нужен. Версия конфига `.rr.yaml`: `version: "3"`.
2. **`WorkflowIdReusePolicy` не существует**: `Temporal\Common\IdReusePolicy` (enum, `RejectDuplicate`) + отдельный `WorkflowIdConflictPolicy` (`03_saga.md` §1 и Q2).
3. **`Saga`**: нет аргумента конструктора `parallelCompensation` (сеттеры); обработчики компенсаций обязаны быть генераторами; `compensate()` надо `yield`-ить (`03_saga.md` §2 псевдокод остаётся верным по смыслу).
4. **Целые числа в интервалах = миллисекунды**, не секунды. Опасно для `%env%`/параметров конфигурации M6.2 (`T-CFG-01`).
5. **Активность регистрируется по реализации**, а не по интерфейсу; интерфейс workflow для клиента статически возвращает `\Generator`, а клиентский стаб отдаёт готовый результат (PHPStan max не пропускает без обёртки `mixed`, см. `TemporalHelloConsoleCommand::asString`). `TemporalOrderSagaStarter` в M6.2 лучше использовать нетипизированный/свой тонкий интерфейс для клиента.
6. `Temporal\Testing` ставится вместе с `temporal/sdk`, но `temporal-test-server` НЕ входит в vendor (скачивается с GitHub, 87 МБ); без него и без RR workflow-тесты (T-W) не запускаются. `03_saga.md` предполагает workflow-тесты как отдельный набор: нужно решение, где хранится бинарь (образ, кэш, `.gitignore`).
7. Время сборки образа 17 мин 29 с (Q1: `grpc` собирается под 8.5, откат на 8.4 не нужен).
8. Профиль `workers` не использован для `temporal-worker` (спека M6.1 требует `up -d temporal temporal-worker`); для M6.2+ решить: если интеграционные тесты делят таблицы/очереди с воркером, перевести сервис в профиль `workers`.
