# M7.2 GraphQL: лимиты и безопасность

## Сделано
- `GraphQlValidationRules` (новый набор на каждый запрос, правила хранят состояние документа): стандартные правила + `QueryDepth(8)` + `QueryComplexity(200)` + `DisableIntrospection`.
- Сложность списка: у `myOrders` своя `complexityFn` = `1 + дети * ceil(limit / 20)` (страница в 100 строк стоит в 5 раз дороже страницы в 20), иначе `limit: 100` был бы бесплатным.
- Introspection: параметр `graphql.introspection_enabled` в `config/services.yaml` (`true`), `when@prod` переопределяет в `false`. В prod `__schema`/`__type` -> ошибка валидации. В dev/test включено.
- Ответ при превышении: HTTP 400, тело `{"errors":[{"message":"Max query depth should be 8 but got 9.","extensions":{"code":"GRAPHQL_VALIDATION_FAILED","status":400}}]}`, ключа `data` нет, ни один резолвер не вызван (тест: ноль SQL после сброса рекордера).
- Тело запроса <= 16 KiB (`GraphQlController::MAX_BODY_BYTES`), иначе 413 `PAYLOAD_TOO_LARGE`; глубина JSON 32.
- Тесты T-F-30: `GraphQlLimitsTest` (глубина 8 проходит / 9 нет, сложность 160 проходит / 240 нет, 10 алиасов с `limit:20` проходят, с `limit:100` нет, introspection включён вне prod), `GraphQlIntrospectionProdTest` (настоящее prod-ядро через `new Kernel('prod', false)`: introspection отклонён, `__typename` проходит), unit `GraphQlValidationRulesTest` (переключатель introspection).

## Не сделано
- Лимит размера тела в спеке не задан, значение 16 KiB выбрано мной.
- Rate limiting / persisted queries не входят в M7.

## Отклонения / находки
- В схеме нет рекурсивных типов, поэтому глубина 8 достижима только через introspection (`ofType`); тесты глубины построены на нём.
- Полный стандартный introspection-запрос (GraphiQL, `getIntrospectionQuery()`) имеет глубину 11 и в dev отклоняется лимитом 8 (зафиксировано тестом). Решение за вами: исключить `__schema`/`__type` из `QueryDepth` в не-prod (подкласс правила) или оставить как есть.
- Prod-тест использует `Kernel` напрямую: тестового клиента в `prod` нет.
