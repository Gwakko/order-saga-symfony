# M3.1 Порты, ошибки, фейки

## Сделано
- `src/Shared/Application`: порты `TransactionManager`, `IdGenerator`; маркеры `Bus/CommandHandler`, `Bus/QueryHandler`; `Output/MoneyOutput`; исключения `ConcurrencyConflict` (retryable), `OrderNotFound`, `InvalidInput`, интерфейс-маркер `RetryableFailure` (колонка «Retryable в саге» из `02_use_cases.md` §6).
- Ordering: порты `OrderRepository`, `ProductCatalog` + `ProductSnapshot`, `OrderSagaStarter`, `OrderSagaSignals`, `KeyDeliveryNotifier`, `DeliveredKeyReader`; исключения `ProductNotFound`, `ProductUnavailable`, `DeliveredKeyNotFound`.
- Inventory: порты `KeyInventory`, `ReservationRepository`; исключения `OutOfStock`, `KeyIsRevoked`, `KeyNotFound`, `ReservationNotFound`.
- Payment: порты `PaymentGateway`, `ChargeResult`, `GatewayChargeStatus`, `RefundResult`, `PaymentRepository`, `ReservationStatusReader`, `OrderPriceReader`, `OrderOutcomeReader`; исключения `PaymentDeclined`, `PaymentGatewayUnavailable`, `CircuitOpen`, `PaymentOutcomeUnknown` (все три retryable), `AmountMismatch`, `ReservationNotActive`.
- `DomainErrorCode::AmountMismatch` (`AMOUNT_MISMATCH`).
- Фейки `tests/Support/Fake`: `InMemory{Order,Payment,Reservation}Repository`, `InMemoryKeyInventory`, `InMemoryProductCatalog` (с проверкой версии как CAS, сбор событий outbox, `failNextSaves`), `FakePaymentGateway` + `GatewayScenario` (успех, отказ, таймаут после/до списания, 5xx, breaker открыт, чужая валюта, чужая сумма; идемпотентность по ключу; счётчики вызовов; `failRefunds`), `SequenceIdGenerator`, `NoopTransactionManager`, `FakeOrderSagaSignals`, `RecordingLogger`, читатели `FakeReservationStatusReader`, `FakeOrderPriceReader`, `FakeOrderOutcomeReader`, `FakeDeliveredKeyReader`.
- Проверка: `make phpstan PHP=` без ошибок (phpat включён).

## Не сделано
- `OrderReadModel`, `ProductReadModel` объявляются в M3.4 вместе с Output-классами (порт возвращает их).

## Отклонения от спеки
- `KeyInventory::reserveAny(...)` из §7 заменён примитивами `lockAvailable`/`find`/`save`/`addIfAbsent` + отдельный `ReservationRepository`. Причина: `01_domain.md` §4.3 велит согласовывать статусы ключа и резервации handler-у в одной транзакции; так логика проверяема на фейках, а SQL (`SKIP LOCKED`) остаётся в адаптере.
- `OrderNotFound` лежит в `Shared\Application\Exception` (нужен и Ordering, и Payment; модули друг друга импортировать не могут).
- `ProductUnavailable` Ordering объявлен отдельно от доменного `Inventory\...\ProductUnavailable` (T-ARCH-02), код тот же.
- Добавлены порты, которых нет в §7: `DeliveredKeyReader` (код ключа для маски в `OrderCompleted`), `OrderPriceReader` (INV-18), `OrderOutcomeReader` (сверка EC-28), `PaymentRepository::findOpenUpdatedBefore`.
- Исключения Application наследуют `Shared\Domain\DomainError`, чтобы иметь `code()` из `DomainErrorCode`.
