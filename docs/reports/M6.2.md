## Отклонения
1. **Спека/M6.1 против SDK**: `Saga` без аргумента, компенсации-генераторы и `yield compensate()`; интервалы переводятся в `CarbonInterval::seconds()` (в yaml секунды); `Temporal\Common\IdReusePolicy`; активности регистрируются по классам реализации; старт через нетипизированный стаб.
2. **`ReserveKey(orderId)`**: команда требует `productId`, активность читает его из `OrderRepository::get()` (вход workflow только `orderId`, INV-18).
3. **Скалярные результаты** активностей; `MarkOrder*`/`CompleteOrder` возвращают `version` (int), `FailOrder`/`StartOrderCompensation`/`MarkOrderManualReview` возвращают `true`: `void` нельзя `yield`-ить без ошибки PHPStan max.
4. **Backoff-коэффициент** в yaml целое (2), к `float` приводится только на границе SDK (`SagaConfiguration`); float в Domain/Application не появился.
5. **`SagaConfigurationHolder`** (статический держатель): SDK сам создаёт workflow без внедрения зависимостей, конфиг передаётся в процесс воркера через держатель. Правило детерминизма разрешает статический вызов только к нему, `Temporal\*`, `Carbon\*`, `self/static/parent`.
6. **Небизнес-сбой вне шага оплаты** (исчерпание ретраев `MarkOrder*`, неизвестное исключение): workflow пробрасывает `ActivityFailure`, заказ остаётся как есть; нужной `FailureReason` в спеке нет. Для оплаты исчерпание = `PaymentUnavailable` (EC-34). Решить в M6.4.
7. `non_retryable` в yaml: FQCN классов. Реальные исключения, а не имена из спеки: `CurrencyMismatch` и `AmountMismatch` -> `FailureReason::CurrencyMismatch`; `ReservationNotActive`/`ReservationHasExpired` -> `ReservationExpired`; `KeyIsRevoked` -> `KeyRevoked`. Добавлен `OrderNotFound` (non-retryable) для `ReserveKey`.
8. **Отмена**: сигнал `requestCancellation`, `guardCancellation`, `IsCancellationRequested`, `CancelOrderBeforeStart` (M6.3) не делались; поэтому T-W-18 без активностей-проверок между шагами. `MarkOrderManualReview` в workflow есть (хвост §2), но не тестируется (T-W-15 в M6.3).
9. **Правки вне списка «На выходе»** (минимальные, без Domain/Application): `Kernel::build` (compiler pass), `UseCaseBus::dispatch()` для use case без Output, `config/services.yaml`, `phpstan.neon`, `Makefile` (`wf-install`), `.github/workflows/ci.yml`, `TemporalClientFactory` (см. ниже).
10. **Исправлен латентный дефект M5** в `UseCaseBus`: `HandlerFailedException::getWrappedExceptions()` индексирован именем обработчика, `[0]` не существовал, и обёртка всегда протекала наружу; для Temporal это ломало сопоставление non-retryable по типу. Теперь `array_values(...)[0]`.
11. **`TemporalClientFactory`**: клиент SDK по умолчанию без дедлайна и с бесконечными ретраями недоступного сервера, потребитель вис, а не падал (EC-58). Добавлены таймаут вызова 10 с и 3 попытки (параметры `temporal.client.*`).
12. Портов в Domain/Application не менялось.
