# M2.4 Payment: `Payment`

## Сделано
- `src/Payment/Domain`: `Payment` (неизменяемый, `create`, `reconstitute`, `recordAttempt`, `markUnknown`, `markSucceeded`, `markDeclined`, `abandon`, `requestRefund`, `markRefunded`), `PaymentStatus` (таблица §5), события `PaymentSucceeded`, `PaymentDeclined`, `PaymentRefunded`, `OrphanChargeDetected`, исключения.
- Тесты `tests/Unit/Payment/Domain` (162): T-U-14 `PaymentTest` (таблица 7×7 на уровне enum и агрегата, `Abandoned → Succeeded` с `OrphanChargeDetected`, повтор `markSucceeded` с тем же/другим `chargeId`, `CurrencyMismatch`, refund только из `Succeeded`).
- Проверка: `make phpstan PHP=` OK, `vendor/bin/phpunit --filter 'Payment.*Domain'` OK.

## Не сделано
- EC-37 (несовпадение суммы) в домене не проверяется: `markSucceeded(chargeId, Currency, now)` по спеке получает только валюту. Проверка суммы остаётся за handler (T-U-36, M3.3).

## Отклонения от спеки
- Спека (§5) говорит «при `CurrencyMismatch` handler переводит платёж в `RefundPending`», но таблица допускает `RefundPending` только из `Succeeded`, а `markSucceeded` с чужой валютой бросает исключение и состояние не меняет. Домен реализован по таблице. Для EC-36/EC-37 (M3.3) придётся либо сначала записать успех, либо добавить в таблицу переход `Pending/Unknown → RefundPending` для неверного ответа. Решение нужно принять до M3.3.
- `markUnknown` идемпотентен (по спеке); `markDeclined`, `abandon`, `markRefunded` повторно не идемпотентны (диагональ таблицы пуста): handler должен проверять статус заранее (EC-49).
- `recordAttempt($now)` (поле `attempts`) добавлен: допустим только в `Pending`/`Unknown`.
- `markSucceeded`/`markRefunded` отклоняют пустой id шлюза (`InvalidGatewayReference`).

## Что проверить вручную
- Решение по EC-36/EC-37 перед M3.3 (см. выше).
