# M4.3. Outbox, relay, inbox, Messenger

## Сделано
- Запись событий: `OutboxWriter::append()` вызывается из `save` каждого репозитория в той же транзакции, что и UPDATE/INSERT состояния (INV-10). Нормализаторы по модулям (`OrderEventNormalizer`, `InventoryEventNormalizer`, `PaymentEventNormalizer`, интерфейс `EventNormalizer` с авто-тегом); в payload только скаляры, код ключа только маскированный (INV-17, проверено тестом).
- `OutboxRelay::publishBatch()`: `SELECT ... WHERE published_at IS NULL ORDER BY occurred_at, aggregate_version, id LIMIT n FOR UPDATE SKIP LOCKED`, отправка через порт `OutboxPublisher` (`MessengerOutboxPublisher` → шина → транспорт), `published_at` после успеха; при отказе транспорта предыдущие строки помечаются, у упавшей `attempts + 1`, остаток пачки ждёт, ошибка пробрасывается (at-least-once).
- `OutboxRelayCommand` `app:outbox:relay` (`--batch`, `--sleep` мс, `--once`), останов по SIGTERM/SIGINT, ошибки пачки логируются, цикл продолжается.
- `InboxGuard::once($consumer, $messageId, $handler)`: `INSERT ... ON CONFLICT DO NOTHING` и эффект обработчика в одной транзакции; дубль подтверждается без эффекта; упавший обработчик не оставляет строку inbox, повтор выполнится.
- Messenger: транспорт `domain_events` (Redis Streams, группа `app`), `retry_strategy` 5 повторов с экспоненциальной задержкой (1 с, ×2, максимум 30 с), `failure_transport: failed` (Redis stream `domain_events_failed`), маршрут `OutboxMessage → domain_events`. В `test` задержки 1 мс и отдельные имена stream.
- `config/services_test.yaml`: публичные сервисы для тестов и тестовый обработчик (`tests/Integration/Support/Messenger`).

Тесты (`tests/Integration/Messaging`):
- T-I-30 `OutboxRelayTest::testUnpublishedMessageIsSentAfterRestart`.
- T-I-31 `TransactionalOutboxTest::testRollbackLeavesNoMessage` (+ откат unit of work при конфликте второй записи, атомарность одиночного `save`).
- T-I-32 `OutboxRelayTest::testCrashBeforeMarkPublishedCausesDuplicate` (+ отказ транспорта посередине пачки, порядок, размер пачки).
- T-I-33 `InboxTest::testDuplicateMessageIgnored` (+ два потребителя, откат при падении, эффект и inbox атомарны).
- T-I-35 `OutboxRelayConcurrencyTest` (3 процесса, 10 раундов по 90 сообщений; каждое отправлено ровно один раз, нагрузка делится поровну 30/30/30).
- T-I-36 `MessengerFailureTransportTest` (реальный Redis: ядовитое сообщение получает 6 попыток, потом попадает в failure transport, остальные два обработаны) + сквозной тест relay → Redis → consumer; `OutboxRelayCommandTest` (`--once` сливает 5 сообщений в stream).

## Отклонения от спеки
- Вместо `InboxMiddleware` сделан декоратор `InboxGuard`: ключ дедупликации `(consumer, message_id)` должен быть именем обработчика, а не транспорта, иначе второй обработчик того же сообщения был бы пропущен. Каждый потребитель оборачивает своё тело в `InboxGuard::once`.
- Failure transport на Redis (`domain_events_failed`), а не `doctrine://`: пакета `symfony/doctrine-messenger` в проекте нет, новых зависимостей не добавлял.
- Порядок выборки relay `occurred_at, aggregate_version, id` (в спеке только `occurred_at`): события одного агрегата с равным временем должны идти по версии.
- `attempts` растёт при каждой отправке (успешной и нет), а не только при сбое.
- Сообщение `OutboxMessage` идёт по Messenger в формате PHP-сериализации (по умолчанию), без JSON-сериализатора.
- `.env`: DSN транспорта без пути `/messages` (путь перекрывает `options.stream`).
