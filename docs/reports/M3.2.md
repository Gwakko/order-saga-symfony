# M3.2 HTTP-команды: PlaceOrder, CancelOrder, RequestRefund

## Сделано
- `src/Ordering/Application/Command/{PlaceOrder,CancelOrder,RequestRefund}`: `*Command`, `*Handler` (`implements CommandHandler`), `*Output` (`final readonly`).
- `PlaceOrderHandler`: каталог, `ProductNotFound`/`ProductUnavailable`, `Order::place` (валюта и цена проверяются доменом: EC-66, EC-67), сохранение в транзакции (событие `OrderPlaced` в outbox через репозиторий).
- `CancelOrderHandler`: чужой заказ = `OrderNotFound` (EC-70), `requestCancellation`, повтор записи при `ConcurrencyConflict` (EC-79), затем сигнал workflow; сбой сигнала не откатывает флаг, пишется `warning` в лог.
- `RequestRefundHandler`: владелец, идемпотентный ответ для `Refunding`/`Refunded`, `startRefund` с `RefundWindow` (по умолчанию 14 суток, внедряется конструктором).
- Тесты (19): `PlaceOrderHandlerTest` (T-U-44), `CancelOrderHandlerTest` (T-U-45), `RequestRefundHandlerTest` (группа `M3.2`).
- Проверка: `make phpstan PHP=` OK; `vendor/bin/phpunit --filter 'PlaceOrderHandler|CancelOrderHandler|RequestRefund'` 19 тестов OK.

## Не сделано
- Нет.

## Отклонения от спеки
- `Validate()` на Command не добавлен: `02_use_cases.md` §0 переносит проверку формата на HTTP-границу (Assert на Request DTO, M5), а формат id повторно проверяют конструкторы VO (`InvalidIdentifier`).
- «ConcurrencyConflict после 3 повторов» реализовано как 3 попытки всего (`CancelOrderHandler::MAX_ATTEMPTS`), после третьей исключение уходит наверх (409). Если нужно «1 + 3 повтора», достаточно поменять константу.
- Сигнал отправляется и когда заказ уже имел флаг (повторная отмена): сигнал идемпотентен, а потерянный первый сигнал так восстанавливается.
- Для `RequestRefund` повтор при `ConcurrencyConflict` не делается (спека требует его только для отмены): 409 уходит клиенту.
