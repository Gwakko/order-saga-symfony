# M4.1. Схема БД и миграции

## Сделано
- `migrations/Version20261124100000.php`: вся схема одной миграцией, `up()` и `down()` (обратный порядок DROP).
  - Ordering: `orders` (включая `compensation_reason` и `cancellation_requested`), `order_view`.
  - Inventory: `products`, `product_keys` (unique `(product_id, code)`), `key_reservations`, `product_availability_view`.
  - Payment: `payments` (unique `order_id`, INV-06).
  - Shared: `outbox_messages`, `inbox_messages` (PK `(consumer, message_id)`), `idempotency_keys` (PK `(customer_id, key)`).
- Partial unique indexes: `key_reservations_one_active_per_key` (`key_id WHERE status='active'`, INV-04) и `key_reservations_one_live_per_order` (`order_id WHERE status IN ('active','consumed')`, INV-05).
- Вспомогательные индексы: свободные ключи товара (`WHERE status='available'`, под `SKIP LOCKED`), истекающие резервации (`WHERE status='active'`), открытые платежи (`unknown/abandoned/refund_pending`, под сверку), неопубликованный outbox, курсор списка заказов.
- Деньги: `bigint` + `char(3)`, все время `timestamptz`, CHECK на диапазоны и допустимые статусы.
- Внешних ключей в схеме нет вообще, ссылки между модулями только uuid-колонки (T-ARCH-04).
- `tests/Unit/Migration/MigrationForeignKeyTest.php` (T-ARCH-04, группа `T-ARCH-04`): статически парсит SQL миграций по карте «таблица → модуль»; таблица вне карты тоже валит тест; парсер проверен на синтетических нарушениях (inline `REFERENCES`, `CONSTRAINT ... FOREIGN KEY`, `ALTER TABLE`).
- `tests/Integration/Persistence/SchemaConstraintsTest.php`: БД сама отвергает вторую активную резервацию ключа, вторую живую резервацию заказа, второй платёж заказа; released/expired не мешают; в `information_schema` нет FOREIGN KEY.

## Проверка
- `doctrine:migrations:migrate -n` → `migrate first -n` → `migrate -n` на `app` и на `app_test`: зелёно (повторено после правки индекса outbox).
- `vendor/bin/phpunit --filter MigrationForeignKeyTest`: 6 тестов, зелёно.
- `make phpstan` без ошибок.

## Не сделано
- Нет seed-данных и команд управления товарами (в спеке не требуются на M4).

## Отклонения от спеки
- `product_availability_view` добавлена в Inventory (её требует порт `ProductReadModel` из M3.4, в `00_overview.md` §5.2 её нет). Состав колонок `order_view` и `product_availability_view` выбран по `OrderDetailsOutput`/`ProductAvailabilityOutput`; `order_view.delivered_key_id` вместо кода ключа (код читается из `product_keys` при выдаче, INV-17), `version` для игнорирования устаревших событий (T-I-34).
- `outbox_messages.aggregate_id` имеет тип `uuid`, не varchar: все агрегаты имеют uuid-идентификаторы.
- Индекс неопубликованного outbox `(occurred_at, aggregate_version, id)`: порядок включает версию, потому что события одного агрегата могут иметь одинаковый `occurred_at`.
- `.env`: `MESSENGER_TRANSPORT_DSN` теперь `redis://redis:6379` без пути (путь DSN перекрывает опцию `stream`, см. M4.3).
