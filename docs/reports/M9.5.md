## Выбор по Q-M9-3

Использованы оба средства вместе.

1. Дедлайн. `config/services_test.yaml` (только окружение `test`) переопределяет сервис `SagaConfiguration`: фабрика `tests/Integration/Support/E2eSagaConfiguration::create` получает `%env(int:TEMPORAL_E2E_CHARGE_SCHEDULE_TO_CLOSE)%` (по умолчанию 0 = не задано). Значение (в e2e 20 с вместо 300 с) принимается только положительное и короче настроенного, иначе `InvalidSagaConfiguration`; затем вызывается обычный `SagaConfiguration::fromParameters`, поэтому инвариант TTL проверяется ещё раз для укороченной таблицы. Только укорочение, значит сумма ScheduleToClose меньше (660 -> 380 < 900), инвариант остаётся верным. `config/packages/temporal.yaml`, `src/` и dev/prod конфигурация не менялись; проверка при компиляции контейнера (`SagaConfigurationPass`) видит настоящие 300 с. Переменную получает только PHP-воркер, который запускает сам тест.
2. Эмулятор: `late-success:32000`. `POST /charges` отвечает `pending` (неизвестный исход, платёж `Unknown`), поэтому `ChargePayment` повторяется до 20 с и сдаётся. Гибель повторов случается раньше 32 с, поэтому `PrepareChargeInspection` видит `Unknown`. Первые попытки `InspectGatewayCharge` видят `pending` (ErrChargePending, повтор), затем `succeeded`; recovery `ChargePayment` находит списание через `GET` и записывает успех. Для T-M9-12 и T-M9-13 тот же режим: платёж остаётся `Unknown`, поэтому `PrepareChargeInspection` говорит «инспектировать» (T-M9-12) или «нет» из-за флага (T-M9-13); компенсация `RefundPayment` находит списание через `GET` и возвращает деньги (в stats у этих двух сценариев один возврат, в T-M9-11 ноль, это проверяется только там).

Время: T-M9-10/11 около 42 с, T-M9-12 и T-M9-13 около 45 с каждый, весь `make test-go-e2e` 2 мин 19 с (сборка образа из кэша).

## Отклонения

1. Спека §7 указывает `--exclude-group slow,go-e2e`; PHPUnit 13 принимает только повтор флага. Исправлен Makefile и текст спеки.
2. Путь теста: `tests/Integration/GoWorker/GoWorkerEndToEndTest.php` (спека: `tests/Integration/.../`). T-M9-10 и T-M9-11 в одном методе (один прогон 42 с вместо двух).
3. Среда для Go-воркера в скрипте: скрипт не использует `docker compose run -d` из спеки, а `up -d --build worker-go` с переменной очереди (так проще остановить и удалить). Уже работающий `worker-go` скрипт останавливает и пересоздаёт (печатает предупреждение).
4. Верхняя граница времени в T-M9-12 (25 с = ScheduleToStart + 5 с запаса на `PrepareChargeInspection` и планирование) выбрана мной, спека формулирует `<= ScheduleToStart + PrepareChargeInspection` без числа запаса.
5. Мутационная проверка e2e-тестов (поломка очереди в профиле) не делалась: опечатку очереди ловит тот факт, что без поллеров T-M9-10 не получил бы `InspectGatewayCharge` на Go-очереди (проверяется `scheduledQueue`), но самой мутации в этом этапе не прогоняли.
